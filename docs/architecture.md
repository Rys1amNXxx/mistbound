# Mistbound 开发结构

这是 Godot 4 的 1–4 人好友合作原型。公共地图指同一个房间共享的营地与野外；房主运行权威游戏逻辑，最多三个客人连接。当前没有跨房间公共世界、账号服务、匹配服务、网络中继或 MMO 分线。

## 模块职责

| 文件 | 职责 | 常见扩展 |
| --- | --- | --- |
| `scenes/main.tscn`、`scripts/main.gd` | 组装世界、联机、镜头与界面；采集键鼠输入；更新 HUD | 新输入方式、镜头模式、设置菜单 |
| `scripts/systems/game_session.gd` | 单人/开房/加入/退出，ENet 与 RPC，周期快照、保存和消息通知 | 平台传输适配、邀请、重连、状态同步优化 |
| `scripts/systems/world_simulation.gd` | 房主的实体生命周期、移动、装备、死亡、个人掉落与全队传送；组装规则并生成/应用快照 | 奖励规则、区域实例、世界进度 |
| `scripts/systems/combat_rules.gd` | 武器冷却、剑的扇形命中、弩箭扫掠碰撞、灼烧和连锁闪电 | 新武器类别、状态效果、遗物触发 |
| `scripts/systems/enemy_brain.gd` | 普通敌人追击/预警、首领冲锋/重击/恢复状态机 | 新敌人行为、首领招式 |
| `scripts/world/zone_view.gd` | 根据区域 ID 生成静态地图、碰撞、入口和敌人出生点；程序化绘制地图 | 添加区域、替换 TileMap/场景、美术资源 |
| `scripts/actors/actor_view.gd` | 玩家和敌人的碰撞体与表现；远端位置平滑 | 动画、受击反馈、客户端移动预测 |
| `scripts/actors/loot_view.gd` | 个人战利品的视觉表现 | 掉落图标、稀有度光效 |
| `scripts/actors/combat_view.gd` | 箭矢快照、命中火花与数字、闪电、冲锋和重击视觉 | 特效与音效；不计算伤害 |
| `scripts/ui/game_ui.gd` | 主菜单、状态栏、探索提示、背包；通过信号请求动作 | 设置、地图、技能与装备详情 |
| `scripts/systems/item_definition.gd`、`item_catalog.gd` | 物品 Resource 数据格式、已注册物品、角色字段校验 | 新物品、装备槽、词条与技能效果 |
| `scripts/systems/save_store.gd` | 角色/世界 JSON 分离，格式校验、备份、临时文件替换 | 版本迁移、多角色、多世界 |
| `data/items/*.tres` | 已有三件物品的名称、描述、增伤和颜色 | 在编辑器里创建与调整物品数据 |

`main.gd` 是组装入口。模块使用普通节点实例与信号通信，当前不依赖 Autoload，也没有第三方插件。

## 输入、权威与表现

本地输入由 `main.gd` 采集后交给 `GameSession`。单人和房主直接交给 `WorldSimulation`；客人通过 RPC 发送移动方向、瞄准方向、攻击意图以及交互/闪避/装备请求。房主校验发送者、区域代次、参数与动作条件，再计算伤害、掉落与拾取。客户端不会提交自己的伤害数值或领取奖励结果。

房主约每 0.1 秒发送一次完整状态快照，加入、切图、击杀、拾取和装备等检查点另走可靠通道。周期状态先压缩；压缩数据超过 1000 字节时转走可靠通道，避免非可靠包超过 MTU。所有状态共享递增的快照序号，客户端拒绝旧序号与旧区域代次，防止跨通道乱序回退。客户端根据快照创建/移除实体并平滑位置。**目前没有客户端预测和回滚纠正**，因此客人的本地移动会受到往返延迟影响；先在局域网验证，后续在 `ActorView` 与输入协议之间加入预测、输入序号和服务端确认。

当前以一个活跃区域承载整个队伍。入口由房主靠近后按 E 开启，全队一起传送；客人只能请求房主开启。后续允许队员独立进入副本时，需要将区域状态、实体集合与快照按实例 ID 拆分，而不仅是改变传送判定。

## 战斗与装备

角色配置使用 `equipped_weapon` 和 `equipped_relic`，分别检查物品的 `slot` 与拥有数量；装备请求仍由房主处理。Q 在已拥有的武器之间切换，不重置攻击冷却；卸下或更换遗物会清空闪电计数。初始角色拥有短刃与手弩。

`CombatRules.attack()` 从武器 Resource 读取伤害、间隔、范围与弹速。剑检查扇形与地形视线；弩产生权威弹体，每帧按完整位移线段选择最先撞到的敌人或墙，避免高速穿透。弹体保存发射时的伤害与遗物配置，切区或发射者离开时清理。

余烬只保留每个敌人的一个灼烧状态，重复命中刷新 3 秒持续时间而不重置半秒计时；共六次基础 4 点伤害。风暴按成功武器命中计数，每第三次命中对主目标和最多两次、每跳 190 像素内的邻近目标额外造成 12 点伤害，检查视线、排除重复目标。只有武器命中进入遗物触发路径，持续伤害和连锁伤害不递归触发。

`EnemyBrain` 暴露 `state`、`state_time`、`windup` 与 `telegraph_*`。首领先预警再行动，冲锋方向在预警开始时锁定，实际位移受墙体限制，每名玩家每次冲锋至多尝试命中一次；范围重击检查距离与地形视线。客户端只读取招式状态绘制提示。

战斗事件携带单调递增 ID，短暂保留在快照中以抵抗偶发丢包。客户端只播放新事件，切区清空旧特效；持续弹体与招式预警直接由快照恢复，晚加入也能看到当前状态。事件与弹体均不写入角色或世界存档。网络协议 v2 与此前单槽版本不兼容，房主会拒绝旧版握手。

## 地图与副本生命周期

区域连接是：`camp ↔ wilds ↔ mine / crypt`。

`ZoneView.build(zone_id)` 清理旧静态碰撞并生成新区域。`get_portals()` 返回入口 ID、标签、目标区域、位置和交互半径；`get_enemy_spawns()` 返回敌人类型和位置；`get_spawn()` 返回队员到达点。交互和战斗由 `WorldSimulation` 处理。

每次进入区域都会重新生成敌人，清空上一片区域尚未拾取的战利品。副本可通过离开再进入重复挑战。世界存档会保存到访区域与累计首领击杀数，**当前不保存现场敌人、地面掉落、玩家坐标或完整地图修改**。退出后再次开始会从营地出发。营地建筑目前是地图表现与未来功能占位。

## 角色与世界存档

- `character.json`（v2）：名称、经验、金币、物品数量、武器槽与遗物槽。每名玩家保存自己的角色；客人离开后可保留收到并保存的角色成长。v1 的单槽装备按类型迁移，首次写入保留原始旧档备份。
- `world.json`：到访区域 `visited`、累计首领击杀 `boss_kills`。仅单人或房主保存，客人不会覆盖自己的世界文件。
- 默认存放于 `user://saves`。本机多进程测试应给每个进程设置不同的绝对路径 `MISTBOUND_SAVE_DIR`，避免共用同一份角色存档。
- 写入采用同目录临时文件和有效旧版本备份；读取主文件失败时尝试 `.bak`。格式版本不匹配时不会将未知结构直接载入。

这些文件位于本地，玩家可以修改。入房校验只用于控制字段和数值范围，不保证角色资产可信。若要加入可信排行榜、交易经济或公开匹配，需要另行设计服务器持有的角色身份和资产。好友房主也属于信任边界，原型没有反作弊保证。

## 添加内容的入口

1. **新区域**：在 `ZoneView` 添加布局、碰撞、出生点与入口；在 `WorldSimulation.enter_zone()` 的允许列表、`SaveStore.REGIONS` 和探索目标文案中登记区域 ID。请保证出生点和入口位于可行走区域，并给碰撞留出通路。
2. **新物品**：按 `ItemDefinition` 创建 `.tres`，指定 `slot`、武器参数或遗物 `effect_id`，加入 `ItemCatalog.ITEMS`，再连接掉落规则。新效果在 `CombatRules` 注册对应逻辑。
3. **新敌人/技能**：在 `EnemyBrain` 或 `CombatRules` 扩展权威逻辑，在 `ActorView` / `CombatView` 增加表现，并将客户端需要的持续状态加入快照。地图脚本只负责指定出生位置和类型。
4. **持久世界事件**：先为事件设计稳定 ID，在 `SaveStore` 加入版本化字段和校验，再在区域生成时应用状态。不要把运行时节点实例 ID 当作存档 ID。

优先保持“单人和房主共用同一套游戏规则”，把传输、输入与视觉放在各自模块中。当前框架适合先扩展玩法和内容，再根据真实延迟测试与人数需求优化联机。
